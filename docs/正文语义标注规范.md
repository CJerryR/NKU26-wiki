# 正文语义标注规范

状态：已接入全站 `.prose` 正文。双主题示例入口 `/component-library/#annotation-pilot`。

## 标注规则

- 文件名、路径、命令、代码标识符、实验材料的精确编号（元件号、菌株号、完整质粒／片段名）、需准确引用的参数表达式和短序列：Markdown 反引号，输出 `<code>`。
- 专业术语首次出现：加粗并解释；后续普通正文。不要仅因英文或缩写加框。
- 关键结论：适量加粗，不整段加粗。
- 物种名、基因名、上下标：遵守科学写作规范，不用代码框代替。
- 普通测量值、单位、页面名称不自动加框；参数只在作为精确表达式引用时加框。
- 长序列、命令组使用独立代码块。短序列必要时写明 5′、3′，不得编造实验数据。
- 注意事项、设计依据、局限性复用现有 callout，保留文字标题，不仅靠颜色区分。

Model overview 的四个模块名固定为 `Molecular Docking`、`Molecular Dynamics`、`ODE & dual-channel sensing` 和 `Economic Benefit`。标题中如附有 ` | ` 后的说明，模块名前缀按上述项目命名保留，其后的说明仍遵循 sentence case；这项例外只适用于 `Model` 页面，不放宽其他标题的句式检查。

## 实现约定

公共样式：`src/styles/annotations.css`，在 `global.css` 中统一导入。所有 `.prose` 正文中的行内 `<code>` 自动生效；新页面使用公共正文容器即可。独立多行代码块保持独立样式。组件示例页仅保留对照主题属性。

正常页面沿用 `html[data-theme="dark"]`；`data-annotation-theme="light|dark"` 只用于双主题对照样例，不是第二套用户主题开关。颜色通过 `--annotation-ink/bg/border` 控制；两种主题共享圆角、字号、间距和换行规则。打印恢复浅色。

行内框不是按钮：不加阴影、悬停效果或点击光标。链接保持链接语义。`pre code` 不加行内边框，长行在代码块内部滚动。

内容主源为 `content/wiki/*.json`，由 `tools/export-tina.mjs` 导出 Markdown；后续正式内容修改应改主源，不单独修改生成文件。

## 修改时验收

1. 按语义逐处标注，不批量匹配所有英文，不更改科研事实与审核状态。
2. 浅色和深色下文字对比度至少 4.5:1。
3. 在 390px 手机和桌面检查中文文件名、长路径换行及整页水平溢出。
4. 验证行内框与代码块相互独立，提示框仍有清晰标题。
5. 修改公共样式后检查组件示例页，并运行构建与内容审计。新增标注时逐页核对实际密度。

行内框按可见字形检查上下留白，不以 CSS padding 数值相等代替视觉居中。当前等宽字体使用非对称上下 padding 补偿字体度量；更换字体后须重新截图测量，不用整体位移假装修正内部留白。

昼夜切换复用 `src/scripts/theme.ts` 的 `nku26-theme` 存储、`html[data-theme]` 与圆形 View Transition；标注不新增开关或独立切换动画。打印始终使用浅色标注。

交互组件 Shadow DOM 中的行内代码由 `toolkit.css` 复用相同的标注颜色变量和字形留白；多行代码与带复制按钮的命令控件保留各自布局。

已落地内容示例：Engineering、Results 的菌株和完整质粒标识，Docking 的模型标识；Experiments、Parts 的数据表按完整单元格识别元件号、菌株号和质粒标识，Sequence 列仅对纯 DNA/RNA 短序列加框。表格不向 CSV 数据写入 Markdown 标记，检索、排序和导出仍使用原值。常规基因／蛋白名称、突变位点与数学公式沿用科学排版。

全文逐页执行计划见 [逐页面标注计划](逐页面标注计划.md)。术语／结论强调按逐页选词清单实施；同页同一术语仅首次强调，每段通常一处、长段可两处。正文重点应同时覆盖研究问题、方法、结果和解释条件，避免只突出积极结果。复用既有提示框，不为了排版新增科研结论。
