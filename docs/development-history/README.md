## 已确定的维护方式

1. 保留 GitHub 当前 main、版本分支和 gh-pages；建立版本导航与开发日志草稿。
2. 按用户明确要求，直接在 GitHub `main` 接入官方已发布的精确 Git 历史，并在根 README 记录迁移前后提交、来源与目标；同步范围是官方 main，不包括本地未审核任务分支。
3. GitHub main 采用官方最终源码和迁移文档；原 main 的提交保留为合并祖先，早期版本分支继续提供旧版源码入口。
4. 逐版本匹配发布回执后，再建立 Tag 与 Release。较早版本如只留存导入快照，写明补存事实，不补造制作或上线日期。
5. 后续在官网发布并核验成功后，同步 GitHub `main` 和版本说明；自动同步尚未配置，仍需按已有上线 bot 的职责衔接。

公开前逐项检查将发布的文档、附件和提交历史中的凭证、个人信息及材料授权。
保留原始证据，另整理可公开的开发记录；不直接公开整个工作区、私有飞书材料、聊天附件和重复打包产物。
既有科研内容待审状态按原记录保留，技术上线不代表科研审核完成。
