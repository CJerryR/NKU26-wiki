# 内页滚动开场（SceneHero）使用说明

有场景配置且 `enabled: true` 的内页，用“随滚动打开”的 2.5D 开场代替原来的 SVG 标题栏；其余页面不受影响。

## 文件

| 文件 | 作用 | 谁改 |
| --- | --- | --- |
| `src/data/scenes/<页面id>.json` | 构图：用到哪些道具、首屏位置、打开后位置、动画区间 | 手写 |
| `src/data/scenes/<页面id>.atlas.json` | 图集坐标与哈希 | 打包脚本生成，不手改 |
| `src/data/scenes.ts` | 登记页面、图集地址（上传 CDN 后在这里换地址） | 手写 |
| `assets/scenes/<页面id>/<道具>.png` | 道具透明源图（不发布） | 渲染脚本或美术 |
| `static/img/scenes/<页面id>-desktop.webp` / `-mobile.webp` | 发布用图集 | 打包脚本生成 |
| `tools/scene-art/props.py` + `sdf.py` | 原九页道具渲染 | 开发 |
| `tools/scene-art/pilot.py` + `mesh.py` | Docking、Awards、Acknowledgements 三页模型与构图 | 开发 |
| `tools/pack_scene_atlas.py` | 打包图集并控制体积 | 开发 |
| `src/components/page/SceneHero.astro`、`src/scripts/scene-hero.ts`、`src/styles/scene-hero.css` | 开场本体 | 开发 |

## 新增或修改一页

1. 准备道具：`python3 tools/scene-art/props.py <页面id>`（每个道具 0.5–3 分钟，无 GPU 的机器上），或把美术交付的透明 PNG 放进 `assets/scenes/<页面id>/`。盖子与底、两半环、拼图这类“必须严丝合缝”的道具，在 `props.py` 里设 `crop=False`，让它们共用同一个画框，再按边界框算位置（见 `tools/scene-art/layouts_p1.py` 里的 `fit()`）。
2. 写构图 `src/data/scenes/<页面id>.json`（可复制 description.json）。坐标单位：横版画布 1600×900、竖版 900×1600，原点在画布中心，y 向下；`w` 为显示宽度；`from` / `to` 为进度 0 / 1 的状态（`s` 缩放、`r` 角度、`o` 透明度）；`win` 为该层运动的进度区间；`depth` 为鼠标视差。
3. 打包：`python3 tools/pack_scene_atlas.py <页面id>`，输出会显示体积与预算。
4. 同名构图和 `.atlas.json` 由 `src/data/scenes.ts` 自动发现；在 `ATLAS_URL` 登记桌面和手机图集地址。
5. `npm run build` 后检查；撤回某页只需把它的 JSON 里 `enabled` 改为 `false`。
6. 没有完整构建环境时，可用 `python3 tools/scene-preview.py <页面id> --vp 1440x900,390x844` 在本机 Chrome 里按滚动 0 / 50% / 100% 截图（开发工具，需要 Python playwright 与 node typescript；它不经过 Astro，**不能替代** `npm run build`）。

## 已有页面（12 页）

Description、Engineering、Results、Model、Contribution（P0）；Experiments、Parts and Collections、Background、Attributions（P1）。P1 四页的构图由 `tools/scene-art/layouts_p1.py` 生成，改完直接重跑它，再跑 `tools/pack_scene_atlas.py <页面id>`。

新增 Docking、Awards、Acknowledgements 三页采用 `tools/scene-art/pilot.py` 生成模型和构图，详见 [3D 试点说明](3D-pilot-20261018.md)。Awards 和 Acknowledgements 正文仍为空。带 `sharedFrames` 的模型部件共用画框，打包时保留相对位置；不要单独裁边。当前共 24 张横竖版图集，均待官方托管。

## 上传 iGEM 后

把 `ATLAS_URL` 里的本地路径换成 static.igem.wiki 地址（一行一个），并在 `content/cdn-assets.json` 登记。本地路径带 `?v=哈希`，CDN 地址不需要。

## 行为约定

### 分辨率适配

- 首屏 CSS 按每个道具的完整边界取景，包括旋转、缩放和鼠标视差余量；导航和实际换行后的面包屑先占位，剩余区域再容纳插画。无需等待动画脚本运行后才能收回越界道具。
- `src/lib/scene-framing.ts` 为整组构图计算统一比例，保留各部件的相对坐标。拼图、受体和配体等共享画框的组团不能分别裁切或单独挪动。
- 滚动时按当前姿态重新取景，只调整整组相机的缩放；保留原场景中心，避免将下方主道具抬到标题上。标题字号独立于插画取景比例。
- 高度不超过640px且宽度至少560px的横屏使用左右分栏，标题在左、道具在右；普通横屏和竖屏沿用原构图。手机和平板给底部大纲按钮预留80px及系统安全区。
- 普通标题栏也有矮屏规则，减少上方留白、约束长标题字号，使主标题不被首屏下边缘和大纲按钮截住。
- 两种方向的图集分别记录解码状态。切换横竖屏后，新的高清图集就绪前继续显示该方向的内嵌预览，避免短暂缺图。
- `npm run test:deployment` 包含全部20套场景（含两套未发布可选页面）的27种尺寸、21个滚动位置与鼠标四角边界测试；实际浏览器验收仍须覆盖当前构建中的18个开场页面和 CSS 首屏。

- 只读 `scrollY`，不监听滚轮，与 `smooth.ts` 的阻尼滚动共存。
- 带锚点进入、后退恢复位置时，按当前位置直接显示对应状态。
- 系统“减少动态效果”或无 JS 时，开场是一张静态首屏（不钉住）。
- 竖屏（宽高比 ≤ 4:5）用单独的竖版构图，只下载竖版图集。
- “Skip to content” 跳到正文 `#content`；开场里的 Skip、Scroll 提示和箭头已移除。
- 道具是示意插图，不表示任何实验数据。
