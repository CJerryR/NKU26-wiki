# 网站排版硬性规则

记录日期：2026-10-19

状态：规则记录，待后续修改与验收。

## 1. 参考范围

以用户指定的 Description 页面开头 Background 区域为排版基准，参考一级章节标题、二级标题、正文、左侧目录及可见的图片容器。Description 后续内容不纳入本次样式参考。

正文宽度和对齐方式按用户补充要求执行：与提示框、图表卡片共用左右边界，普通段落两端对齐。

## 2. 标题与编号

- 英文标题采用 Title Case：主要单词首字母大写；冠词、介词及常见并列连词小写，位于标题首尾时大写。
- 保留 iGEM、pH、基因名等专有名称、缩写和科学名称的规范写法。
- 正文一级章节标题只显示标题文字，删除标题前的章节编号及其后的空格。例如：`Background`、`Project Design & Strategy`。
- 正文二级标题保留 `1.1`、`1.2`、`2.1` 等层级编号，按所在章节连续编号。
- 左侧目录的一级条目保留 `01`、`02`、`03` 等编号；子目录缩进，不显示数字，可使用简短标题。
- 保留大号淡色装饰数字，与一级章节顺序对应。
- 每处编号只有一个来源，不叠加重复编号；正文与目录的章节对应关系保持一致。
- 同一级正文标题在各页面使用统一字号、字重及间距。使用真实标题层级，不用普通段落加粗代替标题。

## 3. 字体、字号、字重与行高

字体统一采用 **Spline Sans**。以下 px 均为 CSS 像素。

### 桌面端及宽度大于 640px 的窗口

| 对象 | 字号 | 字重 | 行高 | 字间距 |
| --- | --- | --- | --- | --- |
| 正文一级章节标题（h2） | `clamp(28px, 2.3vw, 34px)` | `560` | `1.2` | `-0.012em` |
| 正文二级标题（h3） | `24px` | `560` | `1.3` | `-0.005em` |
| 普通正文 | `18px` | `380` | `1.65`（29.7px） | `0.005em` |

### 手机端：窗口宽度不超过 640px

| 对象 | 字号 | 字重 | 行高 | 字间距 |
| --- | --- | --- | --- | --- |
| 正文一级章节标题（h2） | `28px` | `560` | `1.2` | `-0.012em` |
| 正文二级标题（h3） | `21px` | `560` | `1.3` | `-0.005em` |
| 普通正文 | `17.5px` | `380` | `1.7`（29.75px） | `0.005em` |

## 4. 上下间距

| 项目 | 规则 | 桌面端对应值 |
| --- | --- | --- |
| 一级章节标题下边距 | `0.65em` | 18.2–22.1px |
| 二级标题上边距 | `1.65em` | 39.6px |
| 二级标题下边距 | `0.65em` | 15.6px |
| 普通正文段落间距 | `1.1em` | 19.8px |
| 相邻一级章节间距 | `clamp(56px, 5vw, 76px)` | 56–76px |

手机端沿用上述相对单位，按对应字号换算：二级标题上边距 34.65px、下边距 13.65px，普通正文段落间距 19.25px。

相邻上下外边距按浏览器的 margin 折叠规则处理，不直接相加。

## 5. 正文宽度、左右边界与对齐

| 项目 | 硬性规则 |
| --- | --- |
| 对齐基准 | 正文左右边界与提示框、图表卡片的外边缘对齐 |
| 正文宽度 | 占正文栏 `100%`；与组件共用容器，容器上限 `65rem`，随窗口收缩 |
| 正文左右外边距 | `margin-inline: 0` |
| 正文左右内边距 | `padding-inline: 0`，不额外缩进 |
| 段落宽度限制 | 移除普通正文的 `max-width: 74ch` 限制，避免正文比组件窄 |
| 普通段落对齐 | `text-align: justify` |
| 段落末行 | `text-align-last: start`，末行自然左对齐 |
| 手机端页面留白 | 左右各 20px；正文与组件继续共用左右边界 |

组件外框是对齐参照。提示框内部的图标、内边距，以及图片内部留白继续保留。两端对齐规则作用于普通正文段落；标题和图注沿用各自样式。

## 6. 图片与科学排版

- 图片容器沿用参考区域的白底圆角形式。
- 图片保持原始比例、居中呈现，内容完整，不裁切、不拉伸，手机端不溢出。
- 物种学名使用斜体，文献引用使用上标，保留数据、单位和科研含义。
- 正文修改维护 `content/wiki/*.json` 内容源，由既有工具生成 Markdown，不只修改生成文件。

## 7. 验收要求

- 逐页核对正文标题大小写、层级、编号及对应目录。
- 核对同级标题和普通正文的字号、字重、行高及间距。
- 检查正文左右边界与组件外框一致；普通段落两端对齐，末行自然左对齐。
- 分别检查桌面端和手机端，确认图片保持比例且整页无水平溢出。
- 修改 agent 提交改动清单、修改前后证据、测试结果和准确 commit SHA，再由本聊天复验。
- 实施、合并与发布遵循工作区既有目录、归属和锁定流程；功能完成与发布状态分别记录。
