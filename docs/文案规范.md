# NKU-China 2026 Wiki 内容规范（合并版）

版本：2026-10-20。依据线上 V10.2.36 和最新发布的 Description 页整理。

## 0. 地位与范围

本文件是正文页面排版、组件、图片和英文文案的唯一规范，取代以下文档中的对应条目：

- 网站排版硬性规则
- 正文语义标注规范（标注规则一节）
- 全站图注统一记录
- 专业名词负责人确认清单（处理决定一节）
- 各任务记录里零散写下的版式约定

首页场景、Members 和 Attributions 的人物卡片有各自的设计，不受第 2 部分版式规则约束。

**通用约束**

- **改源文件**：一律改 `content/wiki/*.json`（或在 Tina 后台改），再用 `tools/export-tina.mjs` 生成 Markdown；不只改 `src/content/pages/*.md`。
- **不能动的内容**：参考文献原题、精确材料编号、代码、公式、原始 CSV、图片地址、锚点 id、审核状态。
- **科学含义**：涉及基因或蛋白命名、物种判断、数据描述的改动，只标出来，由队伍确认后再改。

# 第一部分：排版

## 1. 字体、字号、间距

字体统一用 Spline Sans。数值均为 CSS 像素。

| 对象 | 桌面端（>640px） | 手机端（≤640px） |
| --- | --- | --- |
| h2（一级章节） | `clamp(28px, 2.3vw, 34px)` / 560 / 1.2 / -0.012em | 28px / 560 / 1.2 |
| h3（二级标题） | 24px / 560 / 1.3 / -0.005em | 21px / 560 / 1.3 |
| 正文 | 18px / 380 / 1.65 / 0.005em | 17.5px / 380 / 1.7 |
| 图注、表注 | 14px / 400 / 1.55 | 相同 |

各项间距：

| 项目 | 取值 |
| --- | --- |
| h2 下边距 | 0.65em |
| h3 上边距 | 1.65em |
| h3 下边距 | 0.65em |
| 段落间距 | 1.1em |
| 相邻一级章节间距 | `clamp(56px, 5vw, 76px)` |

## 2. 版心与对齐

- **版心宽度**：正文和组件共用一个容器，上限 65rem（1440px 窗口下正文宽 1040px），随窗口收缩。不允许页面局部再加 42rem、52rem 这类窄栏覆盖。
- **手机留白**：左右各 20px。
- **左右边界**：正文的左右边界与提示框、图片框、表格的外边缘对齐，不额外缩进。
- **段落对齐**：普通段落两端对齐，末行左对齐。标题、图注、表格、列表都左对齐。
- **手机端对齐**：手机端同样两端对齐，全站统一。Model 页在 ≤760px 改成左对齐的局部样式要撤销。

## 3. 标题与编号

- h2 不带编号，例如 `Background`。
- h3 按所在 h2 连续编号，写成 `1.1 Title`。
- 左侧目录：一级条目显示 01、02，子目录缩进、不显示数字。
- 大号淡色装饰数字与一级章节对应。
- Members 页面按用户明确要求保留四个不编号的 h3：`PI`（`#pi`）、`Advisor`（`#advisors`）、`Student leaders`（`#student-leaders`）和 `Student team members`（`#student-team-members`）。此页面例外不扩展到 Attributions；内容审计会保护这四个标题不被重新加上数字。
- 每页可以有一个页面大标题（`manuscriptTitle`），不编号。
- h4 不编号，只写文字，例如 Results 的 `Design`、`Build and test`。
- 同一页同级小节的命名要一致，例如不能 `The first cycle` 和 `Cycle 1: …` 混用，也不能 `Build & Test` 和 `Build and test` 混用。
- 标题必须用真实的标题层级，不用加粗段落冒充；标题里不放加粗和链接。

# 第二部分：组件与图片（Tina）

## 4. 图片放法：默认嵌入式环绕

以最新发布的 Description 为范例：图片要嵌入正文排布，不要把图片单独夹在段落之间。

| 图片类型 | Tina 设置 |
| --- | --- |
| 竖版、方形或接近方形的单图（宽高比 ≤ 约 1.3:1），且旁边有与它直接相关的正文 | `layout: wrap-right`，`imageWidth: medium`（约 40%）。同一屏连续两张时，第二张用 `wrap-left` 交替 |
| 小照片、图标式插图 | 同上，宽度用 `narrow`（约 32%） |
| 细节多、需要看清的竖图 | 同上，宽度用 `wide`（约 50%） |
| 横版科学图（宽高比约 1.5:1 以上）、多分图拼版、全景照片、图注很长的图 | `layout: full`，通栏显示 |

**嵌入式的写法**

- **配套正文**：只放与这张图直接相关的完整段落，放进 `accompanyingBody`。不拆句，也不搬动段落顺序。
- **桌面效果**：图和图注一起浮动，与正文间距 28px，下方留 16px；文字排过图片高度后恢复通栏；整块上下各留 28px。
- **手机效果**（≤760px）：先显示正文，再显示图片；图片占满宽度，两者间隔 20px。
- **兜底**：配套正文为空时自动退回通栏，所以不要用空的嵌入式块。

**旧版式**

- 不再新增 `left`、`right`、`stack`（并排网格、上文下图）和旧的 `layout` 网格块。
- 现有的旧版式按本节规则改为嵌入式或通栏。Members 和 Attributions 的人物照片组合除外。

## 5. 图片框与图片字段

- **图片框**：白底，1px 边框，圆角 18px，内边距桌面 26px、手机 14px。各页统一，不做局部覆盖。
- **显示方式**：图片等比缩放、完整显示，不裁切、不拉伸。
- **必填字段**：
    - `src`：官方 CDN 地址。
    - `alt`：描述图片内容的一句话，不写 “Figure N |”。
    - `body`：图注，格式见第 9 节。
- **原图**：有压缩预览图时，`src` 填预览图，`originalSrc` 填原图，并设 `openOriginal: true`，读者点击可以查看完整原图。
- **素材托管**：
    - 图片一律通过 `uploads.igem.org` 上传到官方 CDN（`static.igem.wiki/teams/6303/...`），用平台实际返回的地址。
    - 媒体文件不进 Git。
    - 原图的 SHA-256 和 CDN 地址登记到 `docs/*-media.json`。
    - 推送前运行 `tools/check-push-media.py`。
- **授权**：
    - 涉及未成年人或可识别个人的照片，上线前必须有肖像授权。
    - AI 生成的图，图注最后一句写 `Generated with OpenAI GPT Image 2.`（按实际工具写）。

## 6. 其他组件

| 内容 | 用哪个 Tina 组件 | 要求 |
| --- | --- | --- |
| 表格 | `datatable` | 表注放在表格上方，样式与图注相同（14px、不加粗、左对齐）；表格容器圆角 16px，表头和底色随主题；手机端只在表格内部横向滚动；CSV 里不写排版标记 |
| 独立公式 | `equation` | 居中显示，内容是 LaTeX 源码；正文里的行内符号用斜体或上下标，不留括号 |
| 工程循环 | `cycle` | Engineering 用 `display: arc`（半环），每轮配图标；内容与正文一致 |
| 交互网页 | `html` | 放在介绍它的那段正文之后；默认状态要能直接看到结果 |
| PDF、附件 | `pdf` | 显示文件名和简短说明 |
| 提示、注意事项、局限 | 现有 callout | 保留文字标题，不只靠颜色区分 |

组件要嵌在相关正文旁边或紧接在它后面。不要在页面末尾堆一个组件区，也不要给本来是普通段落的内容套上组件。

# 第三部分：文案

## 7. 语言

- **美式拼写**：color、characterize、optimize、analyze、behavior、fiber、liter、center。
- **人称**：团队自称用 we / our。
- **时态**：
    - 已经做过的实验、访谈、活动用过去时。
    - 设计原理、模型说明用现在时。
    - 计划用 will 或 aim to。
- **宣称力度**：
    - 只有数据支持的结论才写 show / demonstrate。
    - 模拟结果和设想写 suggest / could / aim to。
    - 不用 prove、guarantee、perfectly、revolutionary。
- **标点**：英文页面不出现全角标点（（）：；，。）。

## 8. 固定写法

| 写法 | 不要写成 |
| --- | --- |
| NemaKlear | Nemaklear、nemaklear |
| Human Practices（iGEM 专有名词，导航和标题里也大写） | human practices、Integrated human practices |
| wet lab / dry lab（作定语时加连字符：wet-lab work） | Wet Lab、Dry Lab |
| one-step cloning | one step cloning |
| *Arthrobotrys oligospora*（全站统一用这个名字，用不用异名 *Orbilia oligospora* 由队伍决定） | 两个名字混用 |
| NKU-China、iGEM | nku-china、NKU26、IGEM |
| dual-channel（句首写 Dual-channel） | two-channel、Dual-Channel |
| ascaroside #3 (ascr#3)、ascaroside #18 (ascr#18) | ascr 3、ascr-3 |
| Design–Build–Test–Learn (DBTL)（中间是 en dash） | design-build-test-learn |
| Human Practices (HP)、integrated Human Practices (iHP) | human practices |
| test strip（名词）/ test-strip（作定语） | teststrip |
| freeze-dried / freeze-drying | 与 lyophilized 混用 |
| Model 模块名：Molecular docking、Molecular dynamics、ODE and dual-channel model、Economic benefit。标题、导航、卡片、正文链接都用这套 | Molecular Docking、ODE & Dual-Channel Modeling、Eco、Two-channel Sensing |

## 9. 图注、图号、引用

- **图号**：每页从 Figure 1 开始，按出现顺序连续编号。
    - 不允许跳号、重号，也不能沿用原稿编号（如 Figure 9、Figure 22）。
    - 不用 `Figure 3-1` 式编号；ODE 页的 Figure/Table 3-x 也改成 1、2、3。
    - Results 也全页连续编号。
    - 表格单独编号：Table 1、Table 2……
- **图注格式**：`Figure 1. Sentence-case title. 解释……`
    - 全部不加粗，左对齐。
    - 学名斜体，上下标保留。
- **分图标签**：图注里统一写 `(a) …; (b) …`，正文里写 `(Figure 2a)`。不用 `a, …` 这种写法。
- **正文提及图**：写 Figure 2，不缩写成 Fig.。改了图号要同步改正文。
- **文献引用**：
    - 正文用上标方括号，如 ^[1]。
    - 参考文献全站统一 APA 7，不混入 GB/T 7714 格式（[J]、[M]）。
    - 参考文献原题保持原样。

## 10. 物种、基因、蛋白

**物种名**

- 一律斜体。每页首次写全称 *Meloidogyne incognita*，之后写 *M. incognita*。
- 不用 S.c、Mi、Ce、Hg 这类自定缩写，也不用括号定义物种缩写。
- 俗名首次出现时附学名：southern root-knot nematode (*Meloidogyne incognita*)；之后同一页只用一种叫法。
- 菌株名正体：*S. cerevisiae* CEN.PK2-1C。yeast 不斜体。

**基因与蛋白**

- 基因写斜体全大写（*STE12*、*GPR2*），蛋白写首字母大写正体（Ste12、Gpr2）。
- 质粒和构建体名原样保留，并用行内代码：`pRS315-TEF1p-GPR2`。
- 融合蛋白用连字符：GPR2-sfGFP，不用 en dash。
- 氨基酸残基全站统一用单字母：R189、N84V，不和 Arg189 混用。
- 全站只用普通连字符（U+002D），不用不换行连字符（U+2011）。U+2011 会弄坏链接，Results 里两个 Registry 链接因此失效。
- 每一处判断都要交湿实验负责人确认后再改。

## 11. 缩写与强调

**缩写**

- 每页独立处理：正文首次出现写 **全称 (缩写)** 并加粗，之后只用缩写，不再展开。
- 标题、图注、表格、导航不算首次出现。
- 只给学科通用缩写定义缩写，并且这个缩写在该页正文里至少出现 3 次；少于 3 次就直接写全称。
- 复数加 s：PPNs、GPCRs。
- 普通名词保留全称、不需确认。原《专业名词负责人确认清单》的 168 项就此关闭。
- 不使用自造缩写，例如 PPTs、把 G protein 当缩写。

**加粗**

- 用于术语首次定义，以及每段至多一处关键结论（长段可两处）。
- 不整段加粗。

**行内代码**

- 只用于文件名、路径、命令、代码标识符、精确材料编号和短序列。

## 12. 标题措辞

- 所有标题、目录、卡片、页面大标题都用 sentence case；专有名词、缩写、学名保持原样。
- 唯一例外是 Engineering 的 “Goal N:” 前缀。
- 人物或机构标题写成 “Name — affiliation”。
- 主题标题的副标题用 `: ` 分隔。
- 标题里不用双空格分隔。

## 13. 数字、单位、标点

- **数字和单位**：中间空一格，如 5 h、1081 bp、30 °C、10 μL；百分号紧贴数字（20%）。
- **范围**：用无空格的 en dash，如 2–4 h。
- **微**：μ 统一用 U+03BC。
- **引号**：用弯引号 “ ” ‘ ’。
- **破折号**：插入语用 em dash（—），两侧不加空格。
- **e.g. 和 i.e.**：后面加逗号。
- **数字的写法**：同一句里同一类数量写法一致。不能写 39 Parts and four Collections，应写 39 Parts and 4 Collections。

## 14. 链接与页面

- **交叉链接**：段末写 `[Explore … →]`，同一区块只用一种写法。
- **链接、按钮、下载文字、表头**：用 sentence case，例如 `Explore the construction results`、`Download the nematode hunt (Chinese)`。
- **站内引用**：写成链接，不写 `Contribution-Experimental Methods` 这种路径文字。
- **网址**：不在正文里放裸网址。
- **重复翻页链接**：正文里不放与底部翻页按钮重复的 Back / Next 链接。
- **历史原稿**：只出现在 `/source-archive/`。
- **空页**：不允许空页上线。
- **参考文献**：每页参考文献只列本页正文引用过的条目，并按首次引用的顺序编号。

## 作者原稿页面

Project 和 Model 页设了 `preserveAuthorFormatting`，这些页面按以下方式处理：

- **照改的形式问题**：拼写、固定写法、缩写的定义和使用、物种格式、图号、单位、标点、标题大小写。
- **不动的内容**：作者的句子措辞、段落结构、科研内容。
- 遇到改形式就会改变句子意思的地方，只标出来，交作者确认。


## 2026-10-21 用户最新覆盖：首次术语不加粗

保留首次全称与解释，仅移除术语自身的 strong／**；关键结论、标题、表头、人物卡和课程名强调保留。此要求覆盖本文第11节旧的首次术语加粗要求。
