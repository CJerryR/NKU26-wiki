# 发布素材预检

由唯一上线 bot 在已登记的 integration → release 流程内执行；这些检查不改变人工科研审核状态。

1. **来源与版本**：核对用户最新附件、任务交接与素材对应位置。以用户明确指定的最新素材为准；记录原始字节 SHA-256、尺寸、文件大小与提供时间，原图保存在仓库外证据目录。二维码还应解码原图并记录目标，不能仅凭文件名认定正确。
2. **官方托管**：图片使用 `uploads.igem.org` 对应队伍的官方上传入口，视频遵循 iGEM 官方视频流程。使用上传页面实际返回 URL，不猜测路径，不向 Git 新增媒体。平台转换后，重新核对 HTTP 状态、Content-Type、尺寸与 SHA-256；二维码对比转换前后的解码目标。保留旧映射和替换原因。
3. **整个待推历史**：正式推送前先 fetch，在候选所在仓库执行 `python3 tools/check-push-media.py --base origin/main --candidate HEAD`。必须检查每个待推提交，包含中途新增、最终又删掉的素材；只检查最终树会漏掉仍进入 push 的 blob。非零结果禁止推送，回 integration 修复历史并重验。该工具只读，不删文件、不改历史、不放宽服务器门禁。
4. **引用与展示**：构建并验收最终候选；检查对应页面和全站公共组件的真实图片 URL、布局尺寸、移动端、深浅模式、加载结果。二维码需要验证弹层展开、可读尺寸；具备条件时用微信实扫。解码成功不等于在微信完成实扫，两者分别记录。
5. **五分钟漏项盘点**：按根 AGENTS.md 对照队列、任务登记、聊天完成汇报、目录 Git 状态、官方 main 与等价改动，记录清单外未上线项。盘点后至少五分钟再推送，推送前重查新增交接和远端 SHA，候选有变化则重新验收。
6. **上线回证**：从 release 推送后，核对 Pages 流水线、线上 release.json、对应页面实际资源 URL 与 CDN 响应。记录候选 SHA、发布 SHA、流水线和素材映射，更新交接状态与干净基线。

- `static/img/model-overview/overview-8d8c7cc2c80c.png`（1,635,240 bytes）

相同基线至整理后的 `4a1ed5d` 候选检查 1 个提交，返回 0。只在已拒绝且尚未上线的候选上整理历史，原历史另有本地备份；已发布 main 不强推。
